# Guitar Trainer (Flutter: Android, iOS and browser)

A practice companion for guitarists with three sections:

| Section | What it does |
| --- | --- |
| **Metronome** | 30-300 BPM, 2/4 · 3/4 · 4/4 · 5/4 · 6/8, accented downbeat, audible click + flashing beat indicator. |
| **Note Trainer** | A timed drill: find each of the 12 notes once, each on a random string, and see your total time. |
| **Guitar Tuner** | Real-time pitch detection from the microphone (YIN algorithm), note / octave / Hz / cents, flat-sharp meter. |

Dark theme, responsive layouts (phones, tablets, landscape, desktop browsers: a bottom bar on narrow
screens and a side rail on wide ones). The **same code base** runs as an Android/iOS app and as a web app.

## 1. Setup

### Requirements
* Flutter **3.22 or newer** (Dart 3.4+). Check with `flutter --version`.
* For mobile: a **real Android phone** (or iPhone). Emulators have no guitar and often no usable
  microphone. For the browser: Chrome, Edge, Firefox or Safari 14.1+ (desktop or mobile).

### Quick start

```bash
cd guitar_trainer
./tool/setup_platforms.sh      # creates android/ ios/ web/, adds permissions, runs flutter pub get
flutter run                    # on a connected phone
flutter run -d chrome          # in the browser (microphone works on http://localhost)
```

The script is optional; the manual steps are below. This archive contains the Dart source,
assets, tests and tooling; the platform folders are generated by Flutter so they always match
*your* installed SDK version.

### Manual setup (if you don't use the script)

```bash
cd guitar_trainer
flutter create --platforms=android,ios,web --project-name guitar_trainer --org com.example .
rm -f test/widget_test.dart    # template test for the counter app; it does not apply here
flutter pub get
```

#### Android: microphone permission
Add this line inside `<manifest>` (above `<application>`) in
`android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

#### Android: minimum SDK
The `record` package needs **minSdk 23**. In `android/app/build.gradle(.kts)`:

```kotlin
// build.gradle.kts
minSdk = maxOf(flutter.minSdkVersion, 23)
```
```groovy
// build.gradle (Groovy)
minSdkVersion Math.max(flutter.minSdkVersion, 23)
```

If Gradle complains about `compileSdk`, set `compileSdk = 35` (or whatever the error asks for);
recent `permission_handler` versions require a recent compile SDK.

#### iOS (optional)
1. `ios/Runner/Info.plist`:
   ```xml
   <key>NSMicrophoneUsageDescription</key>
   <string>The tuner listens to your guitar through the microphone.</string>
   ```
2. `ios/Podfile`: `permission_handler` only includes the microphone code when asked. In the
   `post_install` block, after `flutter_additional_ios_build_settings(target)`, add:
   ```ruby
   target.build_configurations.each do |config|
     config.build_settings['GCC_PREPROCESSOR_DEFINITIONS'] ||= [
       '$(inherited)',
       'PERMISSION_MICROPHONE=1',
     ]
   end
   ```
   (`ios/Podfile` appears after the first `flutter pub get` / build on macOS.)

### Running in the browser

```bash
flutter run -d chrome                 # development (http://localhost counts as secure)
flutter build web --release           # production build in build/web
```

* **HTTPS is required for the microphone.** Browsers only allow `getUserMedia` on `https://` pages
  and on `http://localhost`. Host `build/web` on any static host with HTTPS (Firebase Hosting,
  Netlify, GitHub Pages, Cloudflare Pages, your own nginx...). For a sub-path add
  `--base-href /your-path/` to the build command. To try it on a phone on your Wi-Fi without
  deploying, use an HTTPS tunnel (e.g. `ngrok http 8080` while serving `build/web`).
* **Permission prompt**: the browser shows its own "Allow microphone" dialog when you tap
  *Start Tuner*. If you blocked it earlier, click the lock icon in the address bar, allow the
  microphone, and press *Try Again*.
* **Sound starts on a tap** (browser autoplay rules): the metronome click is produced the moment you press
  *Start*, so this is automatic.
* **Sample rate**: browsers capture at the hardware rate (usually 48 000 Hz, not 44 100 Hz). The tuner
  reads the real rate from the browser and uses it, otherwise every note would be ~147 cents flat.
* **Web needs no extra setup** beyond the platform folder: no permissions to edit in files, no
  plugins to configure.
* A hidden browser tab pauses everything (same as sending the phone app to the background);
  browsers throttle timers in background tabs, so a metronome there would be unreliable anyway.
* The ♯ / ♭ symbols come from a fallback font that Flutter web downloads on demand, so the
  very first load needs internet access. To work offline, bundle a font that has those glyphs
  (e.g. Noto Sans Symbols 2) under `flutter: fonts:` in `pubspec.yaml`.

### Dependencies

| Package | Why |
| --- | --- |
| `audioplayers ^6.1.0` | Android/iOS: low-latency click playback (two short WAV assets in `assets/sounds/`). |
| `record ^6.0.0` | Android/iOS: live 16-bit PCM microphone stream for the tuner. |
| `permission_handler ^12.0.0` | Android/iOS: microphone permission request, detect "permanently denied", open system settings. |
| `web` | Browser: Web Audio API + `getUserMedia` (only compiled into web builds). |
| `flutter_lints`, `fake_async` (dev) | Lints; deterministic fake-time tests. |

Pitch detection is **pure Dart** (`lib/services/pitch_detector.dart`), so there is no pitch
plugin whose compatibility could break your build, and it behaves identically on phone and web.

**Which implementation runs where** is decided in one file, `lib/platform/platform_services.dart`,
with a conditional import:

| | Android / iOS / desktop | Browser |
| --- | --- | --- |
| Click sound | `audioplayers` + WAV assets | Web Audio oscillator (`web_click_player.dart`) |
| Microphone | `record` (44.1 kHz PCM stream) | `getUserMedia` + Web Audio (`web_microphone_service.dart`) |
| Permission | `permission_handler` | the browser's own prompt, reported as an exception |

The `package:web` dependency keeps a wide version range so it fits the version your Flutter
SDK already pins.

If `flutter pub get` reports a version conflict with your SDK, run
`flutter pub upgrade --major-versions` and check the packages' changelogs for API renames
(`audioplayers`/`record` are the two used outside UI code, each in a single small file:
`click_player.dart`, `microphone_service.dart`).

## 2. Using the app

**Metronome**: tap the big number to type a BPM, use −5 −1 +1 +5, or drag the slider. *Start /
Pause / Resume* and *Reset*. BPM counts **every click**: in 6/8 that means eighth-note clicks, six
per measure. Reset stops the metronome and restores 80 BPM, 4/4.

**Note Trainer**: *Start Training* shuffles the 12 notes and shows the first, e.g.
"Find C♯/D♭ on the 3rd string (G)". Play it, then tap **Found It / Next Note**. Nothing is
counted until you tap. After the 12th note the clock stops and your total time and per-note
results are shown. *Pause* freezes the clock and disables the confirm button. *Reset* clears
everything. The fretboard always highlights the string; switch on **Show answer** to see the
fret(s) where the note is (hidden by default because it gives the answer away).

**Guitar Tuner**: tap *Start Tuner* (this is when the microphone permission is requested), pick
a string or leave **Auto**, and pluck one string, letting it ring. You see the note, octave,
frequency, cents offset, a meter, and **Tune Up / Tune Down / In Tune** (±5 cents is in tune).

**Leaving a section**: switching tabs (or sending the app to the background / hiding the browser tab) pauses the
metronome, pauses the note-trainer clock and **switches the microphone off**. Come back and
press Resume/Start. Nothing keeps running unnoticed.

## 3. Project structure

```
lib/
  main.dart, app.dart            entry point, MaterialApp
  theme/app_theme.dart           colours, text styles, ThemeData
  models/                        GuitarString + standard tuning, TimeSignature,
                                 TrainingTarget, tuner readings/enums
  services/                      all logic, no widgets
    metronome_service.dart       drift-free beat scheduling, BPM / signature / state
    click_player.dart            audio playback interface
    audioplayers_click_player.dart / web_click_player.dart   mobile / browser click sound
    note_trainer_service.dart    session state machine, stopwatch
    pitch_detector.dart          YIN pitch detection (pure Dart)
    tuner_service.dart           mic frames -> level gate -> YIN -> note/cents/direction
    microphone_service.dart      microphone interface + exceptions
    record_microphone_service.dart / web_microphone_service.dart   mobile / browser capture
    mic_permission_service.dart  permission interface (+ permission_handler_mic_service.dart)
  platform/                      conditional imports: picks mobile or browser services
  utils/                         music theory maths, pausable timer, formatters
  screens/                       HomeShell (navigation + lifecycle), 3 screens
  widgets/                       beat indicator, fretboard painter, tuner meter, ...
assets/sounds/                   click_accent.wav, click_normal.wav
tool/                            setup script, click-sound generator
test/                            unit + widget tests (see below)
```

Every service is a `ChangeNotifier` that talks to the outside world through a small interface
(`ClickPlayer`, `MicrophoneService`, `MicPermissionService`) and an injectable clock, which is
what makes the logic testable without a device.

### How the pieces work

* **Metronome timing.** Beats are scheduled against absolute targets on a monotonic clock
  (`next = previousTarget + interval`), never "interval after the last callback", so timer
  jitter cannot accumulate into tempo drift. There is exactly one `Timer`, cancelled before
  any new one is created. Changing BPM re-times the pending beat from the last click. Each
  sound has its own player and restarts instead of stacking, so audio never piles up.
* **Note trainer.** The 12 pitch classes are shuffled once per session; each target draws a
  string independently at random. Fret positions in the fretboard come from
  `(note − open string) mod 12`, i.e. real standard-tuning theory.
* **Tuner pipeline.** mono PCM at the microphone's real sample rate (44.1 or 48 kHz) → sliding ~2800-sample frame → DC removal → level gate
  (RMS < 0.01 = "too quiet") → **YIN** (difference function, cumulative mean normalised
  difference, absolute threshold, parabolic interpolation) → clarity gate → median of the last 5
  results → note / cents against the target string. The cents value is folded by whole octaves,
  so an octave error from the detector (common on low strings with phone microphones) still
  gives the right tune-up/down direction. The last reading is held ~0.7 s so the display does
  not flicker. Raw audio processing (auto-gain, echo cancel, noise suppression) is turned off
  because it distorts pitch.

### Manual checks on a device (what unit tests cannot prove)

1. **Metronome**: audible click on every beat, a higher click on beat 1, the pulse flashes in
   step with the sound. Compare against a phone stopwatch: 60 BPM = 60 clicks in a minute.
2. **Tuner**: play an open A string next to the phone; expect ≈ 110 Hz, "A2". Detune it a
   little with the tuning peg and watch the needle and the *Tune Up / Tune Down* text follow.
3. **Permissions**: deny the prompt (message + *Try Again*); deny "don't ask again" (*Open
   Settings* appears); grant it in settings, come back, *Check Again*.
4. **Lifecycle**: start the tuner, switch to another tab: the microphone indicator in the
   status bar disappears. Same when you press Home.
5. **Sizes**: try a small phone, a tablet and landscape; in a desktop browser resize the window across
   ~840 px (bottom bar <-> side rail).
6. **Browser**: open the page over https/localhost, press *Start Tuner*, accept the prompt, play
   an open string: you should get the same note/cents as on the phone (the tab shows a recording
   indicator while the tuner is on and it disappears when you switch tabs). Press *Start* on the
   metronome and check the click is audible.

## 5. Known limitations

* **Not run in the authoring environment.** The code was written without access to a Flutter SDK
  or a device. The pitch-detection algorithm was validated in a numeric prototype (all six strings
  < 2 cents error, noise and silence rejected) and the code was reviewed carefully, but you
  should expect to run `flutter test` and `flutter run` yourself and fix any small
  version-specific issue the compiler reports.
* **Browser microphone** uses a `ScriptProcessorNode` (deprecated in the spec, but supported by every
  browser and needs no extra JavaScript file). If you ever need to move off it, an `AudioWorklet`
  is the replacement and only `web_microphone_service.dart` would change. The `--wasm` build
  (`flutter build web --wasm`) has not been tried.
* **Click accuracy.** The scheduler is drift-free, but each click still starts when Dart's
  event loop gets to the timer plus the audio engine's latency, so individual clicks can be a few
  milliseconds off. That is fine for practice; for studio-grade timing you would schedule audio
  natively (e.g. with `flutter_soloud`).
* **Tuner** is monophonic: pluck one string at a time. Very low strings on small phone
  microphones are the hardest case; hold the phone close.
* **Performance.** Pitch analysis runs on the UI isolate. In release/profile builds it is a few
  milliseconds per frame; in debug builds on slow devices it can be slower, which is normal.
* Leaving the metronome tab pauses it by design; background audio playback is not implemented
  (on any platform).
